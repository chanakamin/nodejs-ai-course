# משימה מסכמת ליחידה 1: הקמת תשתית Smart Helpdesk 🔨

ביחידה זו נקים מאפס את הפרויקט החדש שילווה אותנו בהמשך הקורס, תוך יישום כל עקרונות הארכיטקטורה המקצועית שלמדנו.

## דרישות הפרויקט הפונקציונליות
יש ליצור ריפוזיטורי **חדש** בגיטהאב בשם `smart-helpdesk-api` ולבנות שרת Node.js + Express (`"type": "module"` ב-`package.json`) המנהל שתי ישויות בזיכרון (מערכים התחלתיים בתוך שכבת ה-`repositories`):

1. **קטגוריות (`categories`)** — מאפיינים: `id`, `name`, `description`.
   * תמיכה בכל פעולות ה-CRUD (`GET /categories`, `GET /categories/:id`, `POST /categories`, `PUT /categories/:id`, `DELETE /categories/:id`).
2. **פניות (`tickets`)** — מאפיינים: `id`, `title`, `description`, `categoryId`, `priority` (`low` / `medium` / `high`), `status` (`open` / `in_progress` / `resolved`), `createdAt`.
   * תמיכה בכל פעולות ה-CRUD (`GET /tickets`, `GET /tickets/:id`, `POST /tickets`, `PUT /tickets/:id`, `DELETE /tickets/:id`).
   * **ולידציה בסיסית ב-Service:** ביצירת פנייה חדשה (`POST /tickets`), יש לוודא ש-`title` אינו ריק, ושה-`categoryId` שנשלח אכן קיים ברשימת הקטגוריות! אם הקטגוריה לא קיימת או שחסרה כותרת — יש לזרוק `AppError` עם סטטוס `400` או `404` מתאים.

## דרישות ארכיטקטורה ותשתית (חובה!)
* קובץ **`CLAUDE.md`** בתיקייה הראשית המגדיר ל-AI את מבנה השכבות וחוקי הפרויקט.
* הפרדה מלאה בין `src/app.js` לבין `src/server.js`, ושימוש ב-`.env` עבור `PORT` (וקובץ `.env.example` שמועלה לגיט).
* חלוקה מלאה לתיקיות: `routes`, `controllers`, `services`, `repositories` (כאשר הפונקציות ב-`repositories` מוגדרות כ-`async`).
* **ללא `try / catch` בקונטרולרים!** כל השגיאות ינוהלו דרך `AppError` ויתפסו ב-**Global Error Middleware** (`errorHandler.js`) שמחזיר JSON אחיד, כולל טיפול בכתובת לא קיימת (404 כללי לניתובים שלא קיימים).
* **Swagger פעיל:** כניסה בדפדפן ל-`http://localhost:3000/api-docs` תציג את כל קריאות ה-API של הקטגוריות והפניות ותאפשר לבדוק אותן בלחיצה על "Try it out".

## הוראות ביצוע ועבודה עם AI 📐
* כל שורת קוד שנכתבה על ידי ה-AI — **חובה להבין היטב!**
* **אין לבנות את הפרויקט בפרומפט אחד!** חובה לחלק את העבודה מול Claude ל-**6 שלבים מתועדים לפחות**:
  1. אתחול הפרויקט וניסוח קובץ `CLAUDE.md` יחד עם ה-AI.
  2. הקמת שלד הפרויקט (`app.js`, `server.js`, `.env`) ובדיקת הרצה בסיסית.
  3. מימוש `AppError` ו-`errorHandler` ובדיקה ששגיאה מכוונת נתפסת ומחזירה JSON תקין.
  4. מימוש כל השכבות עבור `categories`.
  5. מימוש כל השכבות עבור `tickets` (כולל בדיקת קיום הקטגוריה מול `categories.repository`).
  6. יצירת `openapi.json` על בסיס הקוד הקיים, חיבור `swagger-ui-express`, ובדיקת הקריאות (כולל מצבי שגיאה 400 ו-404!) מתוך מסך ה-Swagger בדפדפן.
* **ביקורת קוד בסיום:** לאחר שהכל עובד, שאלי את ה-AI:
  * *"עבור על הפרויקט שלי ובדוק האם הפרתי באחד הקבצים את החוקים שהגדרנו ב-CLAUDE.md?"*
  * *"האם יש מצבי קצה בקריאות ה-POST או ה-PUT שעלולים לגרום לשגיאת 500 במקום שגיאת 400 מבוקרת?"*
* **הגשה:** יש להעלות את הפרויקט לריפו החדש ב-GitHub (לוודא ש-`node_modules` ו-`.env` נמצאים ב-`.gitignore`!), לצרף תיעוד קצר של שלבי העבודה עם ה-AI בתיקיית `ai-log/`, ולשתף אותי כשותפת עריכה (`chanakamin`).
